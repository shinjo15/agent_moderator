# 日本語ライブチャット対照コーパスの検証

## 範囲と参考資料

`tests/fixtures/jev.ts` の既存 `japaneseExamples` 13件を変更せず保持し、`realisticJapaneseExamples` に架空の日本語短文32件（新規16組、参考陽性16件・参考陰性16件）を追加した。総数は45件。既存の命令注入、脅迫の引用報告、架空の非公開住所等も引き続きclient→policyテストを通る。新規32件に実在人物・住所・実サービスへのリンクは使用しない。リンクは予約ドメイン `example.invalid`。16組は配信プレイへの批判/人格攻撃、軽い煽り、属性への差別/一般的な言及、威嚇/ゲーム内の戦闘、性的な要求/衣装の感想、無関係な勧誘/配信関連リンク、本人への攻撃/引用報告、ネタバレ単独/人格攻撃、曖昧な冗談の対照。規則の7分類（`attack`, `hate`, `threat`, `sexualHarassment`, `doxxing`, `spam`, `unrelatedPromotion`）は変更しないが、新規短文の陽性参考ラベルには `doxxing` と `spam` を含めない。ネタバレだけでは対象外。

設計上の参考にしたYouTube公式一次資料（規約違反の判定基準そのものをこの拡張へ移植したものではない）:

- [Spam Policy](https://support.google.com/youtube/answer/2801973?hl=en): 大量・反復的なコメント/ライブチャット、誘導や不自然な宣伝を例示。一方、通常の登録依頼は許容例に挙げられる。ここでの `spam` と `unrelatedPromotion` は拡張独自の評価項目。
- [Harassment & cyberbullying policies](https://support.google.com/youtube/answer/2802268?hl=en): 継続した侮辱、脅迫、非公開の連絡先等の晒しを挙げ、教育的・報道的文脈等の例外を示す。拡張の `attack` / `threat` / `doxxing` / `sexualHarassment` と一対一の同義語ではない。
- [Hate speech policy](https://support.google.com/youtube/answer/2801939?hl=en): 保護属性に関する憎悪表現と、それを非難・反論する文脈等の区別を示す。拡張の `hate` の参考だが、これらのサンプルはYouTubeによる規約違反認定ではない。

## テストの意味と限界

各 `category` は人手設計の参考ラベルであり、Jevの自然文出力でも観測による違反確定でもない。テストではこのラベルから作ったnoul値（該当項目0.8、その他0.1）を模擬HTTP応答として注入し、入力の `state` と固定 `questions` の送信、clientによる応答の読取、policyの閾値判定を確かめる。この構成は値を自分で指定しているため、実モデルの分類精度・誤検知率・曖昧表現の識別力を一切測定・保証しない。既存13件の架空住所のdoxxing参考ラベルも、実際の非公開PII公開を観測した証拠ではない。新規の架空連絡先・架空番地をdoxxing確定陽性とする組と、本文の「また貼る」「何回でも」だけをspam確定陽性とする組は除外した。性的な含みのある単文は相手・文脈で評価が変わりうる。

別に、参考陰性短文を使ったローカル連投の3系列を `createHistory` へ通し、同一投稿者の10秒以内10件で確定、別投稿者の10件目と同一投稿者でも10秒超では未観測となることを対照にした。これは本文の自己申告ではなく、テストで与えた投稿者・ID・投稿時刻から確定するローカル規則の回帰であり、実配信での発生を意味しない。閾値0.8、10秒10件、既存7カテゴリに変更はない。

この環境で自然文を実Jevへ送信するキーを用いた測定は実施していない。実APIでの分類結果・精度は保留。

## RED / GREEN

- RED: 対照コーパスの件数と対になる参考ラベルのテストを先に追加。`npx vitest run tests/jev-policy.test.ts` は `expected 13 to be greater than or equal to 36` で失敗（22テスト中1件失敗）。
- 初回GREEN: 40件/20組のフィクスチャへ置換した段階では同コマンドが49テスト成功、その後、既存連投規則を自然文で再確認する回帰ケース3件を追加して52テスト成功。ただし既存13件を置換していたため、これは最終形ではない。
- レビュー後のRED: 既存13件の保持テストを先に追加し、同コマンドで `expected ... to have a length of 13 but got 40` と失敗（53テスト中1件失敗）。その後、既存13件を元の配列に復元して新40件を別配列へ分離。連投3件は既存実装の回帰テストであり新実装に先行するREDではない。
- 今回のRED: 新規対照の32件/16組とdoxxing・spam陽性参考ラベルの不在を先にテストし、同コマンドで67テスト中2件失敗（実際は40件、doxxingラベルあり）。架空PIIの2組と本文だけの反復宣言2組を削り、既存13件は維持。GREEN: 同コマンド59テスト成功。client→policyには既存13件と新規32件を渡す。連投3件は投稿者・時刻の実装済み規則の回帰確認。

今回の修正後、子paneの `npm run test` は13ファイル/200テスト成功、`npm run typecheck` は成功。親が独立レビュー修正後に単独実行した `npm run package` も終了コード0で、unit 200件、型検査、Chromium MV3 fixture E2E 20件、zip生成が成功した。これは実Jevの自然文評価や実YouTube API接続を検証した結果ではない。
