# 日本語導入手順

## 先に確認すること

併せて [利用規約（案）](terms.md) と [プライバシー・送信データ・削除](privacy.md) を読んでください。

公開配布の適合性は未確認です。YouTube本体UIを変更する機能は撤去しましたが、API由来の判定・第三者送信・ID保持などの確認は別です。改修完了はYouTube承認やストア承認を意味しません。規約確認前の実API利用や一般配布を推奨する手順ではありません。

- 対象は拡張の独立チャットビューアーでの取得・判定・非表示・保存リスト管理です。YouTubeのページ・プレイヤー・標準チャット・リプレイの表示や操作には作用しません。非表示は拡張の独立画面だけに適用します。
- BAN・YouTube投稿削除・投稿・モデレーター権限取得は永久に対象外です。非表示はYouTubeからの削除ではありません。
- 独自バックエンド不要はオフライン動作という意味ではありません。チャット取得にはGoogle、Jevを有効化した判定にはTypeSafeへの外部通信が必要です。
- 投稿者アイコンの表示時はGoogleのYouTube画像配信先にも通信します。画像を取得できない場合は代替アイコンを表示します。画像・画像URLはJevへ送らず、画像要求にAPIキーを付けません。
- 自分のGoogle CloudとTypeSafeアカウント／APIキーを用意します。開発者のキーは配布しません。
- 実キーの認証、通常Windows Chrome、実モデル精度、長時間運用は未検証です。自動テストのAPI fixtureは実モデルの予測・精度測定ではありません。

## 1. Chromeへ読み込む

### ビルドする場合

Node.js 24 LTS以上とnpmを用意し、プロジェクトのフォルダーで次を実行します。キーをファイルやコマンドに書く必要はありません。

```sh
npm ci
npm run build
```

`dist/` が拡張機能本体です。自動検証は開発者向けに [README](../README.md) のコマンドを使います。配布zipを受け取った場合は、先に専用フォルダーへ展開し、その直下に `manifest.json` があることを確認します。ソースフォルダーやzipそのものは選びません。

### Chromeで開発読み込みする

1. Chromeのアドレスバーに `chrome://extensions` を入力します。
2. 「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を押し、`dist/`（zipなら展開先）を選びます。
4. Agent Moderatorが一覧に出ることを確認します。
5. パズル形の拡張機能メニューから固定し、ツールバーにアイコンを出します。
6. 詳細画面の「拡張機能のオプション」またはpopupの設定リンクで設定画面を開きます。

この読み込み・固定は公式「Hello World extension」の「Load an unpacked extension」「Pin the extension」に基づきます。[7]

WSLでビルドした場合は、Windowsのエクスプローラーから参照できる `dist/` をフォルダー選択してください。更新時は再ビルド→拡張一覧の再読み込み→YouTubeページも再読み込みしてください。

旧版からの更新では、既に注入済みのスクリプトや非表示スタイルが残る可能性があります。拡張の更新だけで自動復元されるとは限りません。視聴ページ（チャットiframeの親タブ）、別窓のpopout、リプレイを含む開いているYouTubeの全タブを再読み込みするか閉じて開き直してください。保存リストを消す必要はありません。

### 開発版の判定定義だけを調整する

原本は `public/jev-questions.json` です。読み込んだフォルダーの `dist/jev-questions.json` を直接編集・保存すれば、次の新規評価で反映します。TypeScriptの変更・再ビルド不要で、拡張の再読み込みやブラウザ再起動も不要です。進行中の評価・評価済みコメントは変更せず、再送もしません。保存前にJev判定を停止した場合や読込失敗で停止した場合は、修正後に明示再開してください。

7項目のキーと `type: noul` を維持し、instructionsとcriteriaのtrue/falseは空にしないでください。余分な項目やURLは指定できません。不正・欠落・読込失敗時はJev通信を行わず固定エラーで止まり、古い定義へ戻りません。キー・本文をファイルに書き込まないでください。

build/check/packageはdistを原本で上書きします。保存したい変更はpublic原本にも反映してください。公開版を変えるには定義を同梱した拡張更新が必要です。外部設定の配信・自動取得はありません。

## 2. Google CloudでYouTubeキーを発行する

以下は公式資料の手順です。実アカウントでの画面操作／接続成功は未検証です。

1. 自分のGoogleアカウントでGoogle Cloud Consoleを開き、利用するプロジェクトを作成または選択します。
2. 「APIとサービス」のライブラリで「YouTube Data API v3」を探して有効化します。公式「Before you start」はGoogleアカウント、プロジェクト、APIの有効化を要件としています。[11]
3. 「APIとサービス」→「認証情報」→「認証情報を作成」→「APIキー」で標準APIキーを作成します。サービスアカウントに紐付けたauthorization keyやOAuth client secretを、この拡張のYouTubeキー欄へ入れないでください。[13]
4. キー編集でAPIの制限を「YouTube Data API v3」へ限定します。API制限とアプリケーション制限は別です。[14]
5. アプリケーション制限（HTTP referrer、IP等）はChrome拡張originからの要求と適合する設定を別途確認します。通常のWebサイト向けreferrerやYouTubeのURLを設定すれば動く、と断定しません。制限不一致では要求が拒否されます。無制限キーを安全な解決策として勧めません。[14]
6. Cloud Consoleで、このプロジェクトのAPIクォータ上限・使用量を確認します。[11][12]
7. コピーしたキーを拡張の「YouTube APIキー」欄へ貼り、「YouTubeキーを保存」を押します。キーをチャット、Issue、スクリーンショット、ログ、ソース、`.env`、zipへ貼りません。

拡張は配信管理OAuthやGoogleログインパスワードを要求しません。APIキーによる公開ライブチャット取得成功はまだ未実測で、ここをチェック済みにはしていません。

## 3. TypeSafe公式のJevキーを発行する

1. TypeSafe公式Quick startのPlayground／Consoleリンクから自分のアカウントでログインします。[15]
2. 公式ConsoleのAPI key管理で新しいキーを発行します。公式HTML版は `https://console.typesafe.ai/settings/keys`、公式Markdown版は `https://console.typesafe.ai/keys` を案内しており差があります。利用中Consoleのキー管理画面に従ってください。ログイン後の具体的な発行ボタン名・取消手順は未確認です。[15][16]
3. 課金・credit残高・自動補充の有無・契約条件をConsoleで確認します。Jevは有料APIです。キー発行だけで無料・無制限と考えないでください。Master customer agreement §8ではInput送信によるcredit消費と、利用者がopt-inした自動補充を説明しています。[20]
4. 「Jev APIキー」欄へ貼り、「Jevキーを保存」を押します。

TypeSafe公式のキーを使います。別事業者のgatewayキーや他のAIサービスのキーとは区別してください。[6]

## 4. 保存結果を確認する

- providerごとの表示が「設定済み」になればローカル保存状態を確認できています。接続確認はしないので、認証成功・credit・利用可能クォータの保証ではありません。
- 保存済みキーの文字列はUIへ戻しません。保存後に入力欄が空になるのは想定動作です。
- 空欄で「保存」は既存キーを保持します。削除は必ずproviderの「キーを削除」を使います。
- キーはこの拡張専用の `chrome.storage.local` に保存します。Chrome同期・Web localStorageは使いません。暗号化された秘密保管庫ではなく、端末／ブラウザプロファイルにアクセスできる人からは守れません。

## 5. 取得開始・停止、Jev明示有効化

初回はpopupの「設定を開く」から、利用規約案・プライバシーポリシー案・YouTube利用規約・Googleプライバシーポリシーと外部送信の説明を読み、「利用規約（案）とプライバシーポリシー（案）に同意し、データ送信・費用の説明を確認しました」にチェックして「同意を保存」を押してください。利用規約は拡張に同梱したページで読めます。開発版の案への確認・同意で、施行日未定・正式施行ではありません。同意前でもキーは保存できますが、取得・Jev送信は開始できません。同意した説明の版4だけをこのChromeプロファイルに保存し、再起動後も保持します。登録時のコメント本文の端末内保存導入のため旧版3以前は自動移行せず、版変更・欠落・読取失敗時は再同意が必要です。既存一覧の確認・解除・全削除は未同意でも可能です。保存は通信を自動開始する操作でも、投稿者本人の同意や規約適合を保証する操作でもありません。通常のYouTubeページ閲覧は対象外です。

1. `https://www.youtube.com/watch?v=...` または `/live/...` の対象視聴タブを開きます。
2. そのタブで拡張アイコンを押し、「この動画のチャットを取得」を押します。
3. タブ欄・アドレスバーのある通常のChrome別ウィンドウに開いた独立ビューアーで対象動画IDを確認し、下部の「取得を開始」を押します。YouTubeキー未設定なら「設定を開く」で先に設定します。
4. ビューアーのウィンドウは本人が移動し、YouTubeと横に並べて使えます（目安7:3）。YouTube側のウィンドウを自動移動・サイズ変更する機能はありません。裏の画面はブラウザによって取得が遅くなる場合があります。初回取得は直近の一部で、全履歴ではありません。末尾を閲覧中だけ新着へ追従し、過去ログからは「↓ 最新へ戻る」で末尾へ移動できます。
5. Jevを使うときだけ、「利用と判定について」の送信範囲／費用の説明を読み、下部の「Jev判定を有効化・再開」を押します。キー保存だけではJev送信しません。有効化後の新着を順に評価します。スコアや状態の詳細は各行の「コメントの詳細」から開きます。
6. 「Jev判定を停止」はJev送信を止めます。YouTube取得とローカル連投の判定は継続します。
7. 取得中に同じ親のYouTube視聴タブで別ライブへ移動すると、待機制限を守ってそのライブへ自動で切り替わります。他タブ・別ウィンドウには追従しません。旧コメント・判定待ち・本文の履歴は破棄し、新しい配信者の非表示リスト確認前は本文・アイコンを表示しません。正常な切替では有効だったJevだけを引き継ぎ、無効・失敗停止した判定は再開しません。
8. 「取得を停止」は取得とJev判定を止めます。切替の待機中にも操作でき、停止中の移動では新しい動画を選ぶだけで、自動取得しません。「取得を開始」でその動画を開始できます。monitorを閉じる／離れる、視聴タブclose、対象外ページへの移動、取得失敗、YouTubeキー差替え／削除、同意の変更、全非表示データ削除では停止します。Jevキー差替え／削除はJev判定を停止します。終了ライブやチャットなしの配信でも停止し、他のライブへは乗り換えません。
9. 同じ動画のクエリ変更・視聴タブの再読み込みでは取得を維持します。別originへの移動で一時的なURL参照権限が失われた場合は停止し、YouTubeへ戻るだけでは再開しません。拡張ポップアップから対象を選び直してください。monitor自体の再読み込みでは手動開始・Jev無効に戻ります。バックグラウンド再作成時も、確認できないJev有効状態は自動復活させません。

Jevへ送る投稿データは、対象と既取得の同一投稿者の直近60秒以内、対象込み最大20件の本文と投稿時刻だけです。message ID、author ID、videoID、他投稿者の履歴は送信stateへ入れません。APIキーはTypeSafe認証用ヘッダーに必要ですが、投稿データには入れません。本文に氏名・住所等が書かれていれば本文として送られ得ます。「IDを送らない」は匿名化の保証ではありません。追加の履歴APIは呼びません。

判定の厳しさは設定画面の「フィルターの強さ」で選び、保存してください。「詳細設定」では判定の基準値を指定できます。保存した設定は新しい評価に適用され、過去コメントの再評価や保存済みリストの自動解除は行いません。判定基準は実モデルの精度保証ではなく、API失敗を悪質／安全の確定根拠にはしません。

## 6. 非表示一覧・明示解除・リスト削除

「非表示一覧」ボタンの小さいバッジは、この配信者の非表示投稿者のユニーク人数です。0は0人、…は確認中、!は読取失敗、—は対象なしです。一覧にはAI・連投それぞれ最初に追加した対象の本文を「登録時のコメント」として1投稿者1件だけ表示・端末内保存します。長文・改行もそのまま表示し、後続投稿で上書きしません。同じ配信者の別ライブでも元の登録時のコメントであり、現在の配信での投稿とは限りません。本文なしの既存データは「確認できません」、空本文は「本文は空です」と表示します。追加API取得・Jev再判定・外部送信はありません。個別解除・全削除で保存本文と元の動画IDも削除します。停止・ブラウザ再起動では消えません。

登録の対象は確定したJev悪質判定または既取得投稿によるローカル連投だけです。判定待ち・失敗では登録しません。保存済みIDに一致する既存・新着のコメントは独立ビューアーから非表示にします。リストを読み取れない間は本文の表示を保留し、「非表示一覧」から再試行できます。YouTube本来のコメントは変わりません。

1. popupから対象のwatch/liveタブを選び、「取得を開始」で配信者を確認後、ビューアー下部の「非表示一覧」で投稿者名の一覧を確認します。配信者は既存の動画API応答のチャンネルIDで識別し、名前・タイトルやコメント投稿者IDでは決めません。確認できるまで一覧を空の正常状態にせず、本文・アイコンの表示も保留します。取得失敗では時間をおいて明示再開してください。未取得名や以前のID-onlyデータは「名前不明」と表示し、「投稿者ID」を開くと補足IDを確認できます。名前では照合せず、同名でも別IDなら別投稿者です。別の配信者を確認・解除するにはその配信のタブをpopupから選び直します。全配信一覧はありません。
2. 対象投稿者の「非表示を解除」を押します。同名の場合は補足IDも確認してください。独立ビューアーが現在保持している対象行だけが再表示されます。非表示分を含め直近200件までの保持で、上限超過・再読み込み・動画切替で失った過去コメントは復元しません。YouTubeの表示は変更しません。
3. リストは配信者のチャンネル別にこのChromeプロファイルへ保存し、同じ配信者の別ライブにも再判定を待たず適用します。他の配信者には適用しません。同期・自動期限はありません。「取得を停止」、monitorを閉じる、キー削除、ブラウザ再起動でも保存リストは解除されません。API確認済み動画の配信者IDとの対応も端末内に保存するため、その動画を選び直せば取得開始・追加通信なしで一覧確認・解除ができます。未確認動画は取得開始が必要です。再取得開始では古い対応を失効して再確認し、失敗時は旧対応へ戻しません。取得とJev判定は自動再開しません。
4. 個別解除は同じ配信者の別ライブにも反映します。対象のIDと名前はリストから外れますが、解除前の結果と旧保存の後日移行による復活を防ぐ世代情報は残ります。解除後の新しい悪質投稿は再登録され得ます。旧動画別の保存は、現在アクセスした動画の既存API応答で配信者を確認できた分だけ遅延移行します。追加APIや全保存動画のまとめ取得はせず、未解決の旧保存は保持します。保持・削除の詳しい範囲は[プライバシーポリシー](privacy.md)を確認してください。
5. 全配信分を削除するには、同じpopupの「設定を開く」から「全配信の非表示データを削除」を押し、確認画面の「削除する」で実行します（キャンセル可）。取得・判定を停止し、新旧のID・名前・世代情報・移行済み動画の記録・空の保存項目を未解決の旧動画分も全て削除します。APIキー、判定の基準値と他の設定、API待機期限は残します。YouTubeへの通知・表示変更はありません。削除を確認できない場合は再試行してください。提供元の送信済み情報やYouTube投稿の削除、表示済み本文の消去ではありません。明示再開後の新しい判定では再び登録され得ます。

API由来IDを解除まで保持する仕様のYouTube規約適合性は未確認です。

## 7. 費用・Googleクォータ

- Jevの料金は利用者のTypeSafe契約に従います。公式トップは「$42 / Per Billion input tokens」と表示しますが、実際の請求単価・税・credit・自動補充条件はConsole／Orderを確認してください。広告の速度や料金例を本拡張の実測値として使いません。[5][20]
- 本文に加え質問／rubricと文脈も入力です。コメント数だけでは請求額を決められません。API応答のusageとConsoleを確認し、不要時はJevを停止します。拡張に利用額上限や請求額確定表示はありません。
- Googleのquota unitはJevの料金とは別です。取得時点の公式表は `videos.list` と `liveChatMessages.list` が各1 unit。無効な要求も少なくとも1、追加ページごとにも消費します。[12]
- 公式の他endpoint合算の既定割当は日次10,000 units、日次リセットはPacific Timeの深夜。上限は変更され得るため、自分のCloud Consoleの表示を優先します。上限を超えたら停止し、割当／リセットを確認します。別projectへ切替えて制限を回避しないでください。[11][12]
- Google APIの実料金・請求・クォータ消費は未測定です。quota単位を金額と同一視せず、他Cloudサービスの請求まで無料と保証しません。

## 8. 各キー削除・提供元失効・アンインストール

### 拡張に保存したキーだけを削除

設定画面で「Jevキーを削除」「YouTubeキーを削除」をそれぞれ押し、そのproviderが「未設定」になったことを確認します。一方を削除しても他方は削除しません。Jevだけ削除してもYouTube取得は別です。

### 提供元のキーも失効させる

拡張内の削除は提供元アカウントのキー失効ではありません。漏洩が疑われるときは、Google Cloud Consoleの認証情報で当該キーを削除／ローテーションし、TypeSafe Consoleのキー管理でも取消を確認します。Google公式は新キーへの置換後に旧キーを削除するローテーションを説明しています。TypeSafeログイン後UIの取消ボタン名は未確認で、必要なら公式supportへ問い合わせます。[13][20]

### リスト／全ローカルデータを削除

リストの非表示IDは前節の個別「非表示を解除」で除外できますが、解除の世代情報は残ります。リストの解除でキーを削除しません。キー削除でリストを削除しません。全ローカルデータの消去には拡張の削除が必要です。ブラウザの閲覧履歴／キャッシュ削除は拡張の保存データの削除方法ではありません。[19]

全ローカルデータを捨てる場合は取得を停止してmonitorを閉じ、`chrome://extensions` でAgent Moderatorを「削除」します。Chrome公式は拡張を削除すると `storage.local` が消去されると説明しています。再インストール後のキー／リスト復元は保証しません。[19]

アンインストールしてもGoogle／TypeSafeアカウント、提供元キー、すでに送信したデータ、課金契約・自動補充、既存請求は消えません。提供元に送ったデータの削除は提供元で別途依頼してください。YouTube上の投稿をこの拡張から削除する機能はありません。

| 状態 | 対処 |
| --- | --- |
| Chromeに読み込めない | 選んだフォルダー直下にmanifest.jsonがあるか、ビルドが成功したかを確認。エラー共有時にキーやキー付きURLを含めない |
| 設定済みなのに認証失敗 | 保存と認証は別。provider、API有効化、キー失効、アプリケーション／API制限を確認。空欄保存では削除できない |
| 取得を開始できない | YouTubeキー、視聴動画URL、popupで選んだ対象を確認。開始前・終了・チャット無効・非公開／取得不能を区別する |
| quota／429／混雑 | 自動retryしない。Cloud割当／TypeSafe残高と、表示された待機時間を確認し、期限後に明示再開。連打やproject切替で回避しない |
| network／不正応答 | 通信が止まっていることを確認。障害解消後に明示再開。失敗を悪質判定へ読み替えない |
| Jev未判定 | 明示有効化前の投稿、履歴窓外、時刻不明、停止／障害を区別。失われた本文の追加取得はしない |
| 表示が遅い | monitorを閉じていないか確認。裏タブのthrottling、判定の直列処理は速度保証なし |
| 動画を移動した | 新動画の視聴タブでpopupから選び直して開始。旧動画の取得は続けない |
| 再起動後 | 自動取得／Jev判定を期待せず明示開始。非表示リストは保持される |
| 更新したのにYouTubeのコメントが見えない | 旧版のスクリプト・非表示スタイルが残る可能性があります。視聴・popout・リプレイの全タブを再読み込みするか閉じて開き直す。リスト削除は不要 |
| YouTubeで非表示にならない | 非表示は拡張の独立画面だけです。YouTube標準チャットを閉じたい場合は本人がYouTubeの標準UIで操作してください |
| 拡張の本文表示が保留される | 保存済み非表示リストの読取を確認できない間は本文を表示しません。「非表示一覧」の再試行を使い、対象動画も確認してください |

問い合わせにはOS、Chrome／拡張版、実施手順、秘密を除いた固定エラー、再現可否を記録してください。DevTools Networkには認証ヘッダー／キー付きURL／他人の本文が含まれ得ます。実キー入りのprofileや生通信ログを提出しないでください。
